## Ceph Server 到底是什么

Ceph 是一个统一分布式存储系统，一个集群同时提供三种接口：对象存储（兼容 S3 的 RADOS Gateway）、块存储（RBD，可以给虚拟机当硬盘）和文件系统（CephFS）。它跑在普通商用硬件上，这是它和传统 SAN 最大的区别——你不是买一台昂贵的存储阵列，而是用一堆普通服务器加一堆硬盘，自己拼出一个可横向扩展的存储集群。

集群里有几种角色，每种对硬件的要求不一样：

- **OSD（Object Storage Daemon）**：实际存数据的进程，通常一块盘对应一个 OSD。这是集群里数量最多、最吃资源的角色。
- **Monitor（ceph-mon）**：维护集群状态图，要求不高，但一定要稳，官方建议至少放在 SSD 上。
- **Manager（ceph-mgr）**：负责监控和仪表盘，与 Monitor 常驻同一批节点。
- **MDS（ceph-mds）**：CephFS 专用，单线程为主，吃高主频 CPU。

"ceph server" 在实际语境里，指的就是承载这些进程的服务器节点。官方文档对最小集群的定义是：至少 1 个 Monitor、1 个 Manager，以及两个以上 OSD。但生产环境几乎没人这么搭，原因在下面。

## 为什么 Ceph 至少要三个节点

Ceph 默认三副本写入：一份数据要写成功，必须落到三个不同的故障域。少于三台机器时，副本无法分散，要么数据不可用，要么集群干脆拒绝写入。所以三节点是事实上的最低门槛，四个 Monitor 节点可以容忍一个节点宕机时仲裁仍然成立。

三节点也意味着容量的取舍。三副本下，三个节点总容量的三分之一用于冗余，挂掉一个节点后剩余空间要能接住重建流量。论坛里一个常见估算：3 节点集群的最大可用容量约 66%，实际规划时一般按 50% 左右预留，给恢复和扩容留余量。

单机也能跑 Ceph，Red Hat 官方博客甚至专门写过教程。但单机 Ceph 没有任何冗余意义，只能用于学习和测试。如果你是为了生产环境搜这篇文章，直接按三节点起步规划预算。

## 规划 Ceph Server 硬件：数字都要对得上

官方文档给出的经验数字值得抄下来对着算：

- **CPU**：每个 OSD 至少 1 核，推荐 2 核起步。NVMe OSD 很吃 CPU，单块 NVMe OSD 在实际集群里用到 5–6 核并不夸张。超线程对 Ceph 有利，官方直接推荐开启。
- **内存**：BlueStore OSD 默认内存目标 4GB，加上恢复和再平衡时的峰值，按每个 OSD **约 8GB** 预留比较稳妥；官方还建议额外留 20% 余量防止 OOM。Monitor/Manager 节点：小集群 32GB 够用，300 个 OSD 以内 64GB，更大规模 128GB。
- **存储盘**：官方建议 OSD 盘不小于 1TB——小盘元数据占比过高，低于 100GB 的盘几乎没有效率。OSD 数据盘、操作系统盘、BlueStore 的 WAL+DB 尽量分开。
- **网络**：官方底线是 10Gb/s。理由很具体：1Gb/s 网络复制 1TB 数据需要 3 小时，10Gb/s 只要 20 分钟；10TB 在 1Gb/s 下要 30 小时，10Gb/s 下 1 小时。恢复速度直接决定故障窗口期的风险。

还有一个常被忽略的点：企业级 SSD。官方明确说廉价 SSD 是"虚假的经济性"，缓存写满后性能会断崖式下跌，而且缺少断电保护（PLP）。Monitor、Manager、CephFS 元数据池、RGW 索引池，无论数据盘用什么，都建议放在企业级 SSD 上。

把这些数字放一起，就能算出一台 Ceph OSD server 的轮廓：至少 6–8 个大容量盘位、每盘配 1 核以上 CPU、每 OSD 预算 8GB 内存、10G 起步的网络。如果走全闪路线，还需要 U.2 NVMe 盘位和更多的 CPU 核心。

## 从零到集群：部署路径速览

硬件到位后，搭一个三节点 Ceph 集群的主流路径其实不长。以 cephadm（官方推荐的部署工具）为例：

1. **准备三台机器**，装 Linux，设好主机名和 SSH 互信；操作系统、WAL/DB、OSD 数据分别放在不同盘上（Sharktech 机型上一般用 M.2 装 OS 和 WAL/DB，U.2 或 SATA 盘位做 OSD）。
2. **在第一台上引导集群**：`cephadm bootstrap`，它会带起第一个 Monitor 和 Manager，并生成仪表盘。
3. **把另外两台加入集群**：通过 `ceph orch host add` 注册主机。
4. **让 cephadm 自动创建 OSD**：指定"任何可用盘都可以做数据盘"，它会把每个盘位格式化成一个 BlueStore OSD。
5. **按需添加上层服务**：RBD、CephFS（会自动部署 MDS）、RADOS Gateway（S3 兼容接口），同样是 `ceph orch` 一条命令的事。

在 Proxmox VE 里这条路径更短：图形界面里勾选 Ceph 就能装好 Monitor/MGR/OSD，虚拟机直接挂 RBD 硬盘，官方文档专门有超融合部署的章节覆盖这个场景。Kubernetes 用户则通常用 Rook 把 Ceph 跑进集群里。
